# 八項功能實作與驗證

本次以 PR #1 的草稿/備份版本為基準，延續已擷取的正式站前端，完成以下八項功能。更新推送至 PR #1 分支，不自動合併 main 或取代正式 Worker。

| 順序 | 功能 | 實作 |
|---|---|---|
| 1 | 草稿恢復 | 原圖、頁序、旋轉、裁切、文字與表單自動保存；多分頁獨立、選取恢復、離線可用。新增報帳欄位也列入草稿。 |
| 2 | 拍攝品質提醒 | 384px 樣本亮度、Laplacian 變異與過亮區比例；匯入照片後自動檢查，亦可手動重查。不阻止使用者保留圖片。 |
| 3 | 完整備份/還原 | 含文件、原圖、聯絡人、草稿與範本的 .smartscan.json；SHA-256 驗證、預覽後確認、以新 ID 新增副本、單一交易全部回滾。 |
| 4 | PDF 匯入/合併/拆頁 | PDF.js 本機 rasterization，最多 40 MiB、合計 20 頁，圖片最長邊 2400px；可與照片調序合併。支援 1,3-5 頁碼選取匯出、逐頁 PDF ZIP、取消與失敗回滾。jsPDF 同源保存以支援離線產檔。 |
| 5 | OCR 對照校正 | 每頁原圖/全文對照；有效 OCR bbox 可點字標示原圖；編輯後清除舊座標，避免錯位。檢查頁面與主編輯器版本，避免覆蓋後續修改。 |
| 6 | 敏感資訊遮蔽 | 拖曳或百分比數值畫框，以向外取整黑色像素燒入新 PNG；替換目前頁原圖並清除該頁 OCR、聯絡人/AI/翻譯/收據等衍生欄位；另存遮蔽工作副本，不覆蓋原文件。 |
| 7 | 重複文件提醒 | SHA-256 完全相同原圖的匯入確認；存檔前比較原圖、頁序與變換，排除正在更新的原文件；不以檔名判重，不自動刪除。 |
| 8 | 收據報帳流程 | 店家、內含稅額、付款方式、編號、備註、草稿/待報帳/已送出/已核准/已撥款狀態；狀態/日期/標籤篩選；CSV/Excel 與含憑證圖片的 ZIP。不同幣別分開合計，整數分驗證稅額。 |

## 操作入口
- 掃描頁：草稿與恢復、拍攝品質提醒、PDF 整理、敏感資訊遮蔽。
- 文字頁：原圖與 OCR 逐頁對照校正、報帳資料與狀態。完成校正後按「儲存此頁校正」；報帳資訊填妥後回掃描頁按「儲存到文件庫」。
- 文件頁：完整備份/還原；支出報告可按報帳狀態篩選、下載報表與憑證圖片。

## 產品界線
- 品質提醒為啟發式，空白白紙/特殊版面也可能觸發，尚未以真實手機照片校準；不宣稱準確偵測模糊或反光。
- PDF 以圖片匯入，不保留原文字層、向量、附件、表單、簽章或原始 PDF bytes。密碼 PDF 請先解鎖；匯入後需核對字型/內容。選頁匯出和逐頁 ZIP 為圖片 PDF；一般多頁 PDF 可沿用既有 OCR 搜尋文字層選項。
- OCR 對照依現有辨識座標提供輔助；沒有有效座標時仍可逐頁全文校正。測試使用固定 bbox fixture，不是新一輪 OCR 準確率測試。
- 遮蔽只修改目前工作副本，文件庫與其他分頁/舊草稿原件保留；完整備份仍可能包含原件。分享時使用遮蔽後產生的 PDF。其他頁若有同樣資料需另外遮蔽。無法從黑色像素還原該頁原內容，不使用可移除的 PDF 遮罩。
- 重複提醒只檢查完全相同的原圖內容；重拍、重新壓縮或相似文件不保證辨識。
- 報帳流程是個人資料整理，不提供組織簽核、付款、稅務判定或會計系統串接。PDF 匯入的附件是轉換圖片，原 PDF 不保留。附件 ZIP 上限 128 MiB，請確認原件個資後分享。
- 備份容量、未加密及 OS 強制終止界線沿用 RECOVERY-BACKUP.md；尚未完成真實 iPhone/Safari、大量資料記憶體壓力與字型相容性驗收。

## 拍照後自動裁切
拍照入口預設勾選「拍照後自動裁切文件邊界」，可關閉。匯入後以最長邊 640px 的分析圖偵測完整可見、與背景有明顯對比的淺色文件；加保留邊距，低對比、觸邊或不明確時保留原圖並提示手動調整。相簿入口不自動裁切。
裁切只保存相對原圖的範圍，原始 File 不改動；縮圖、PDF 與 OCR 沿用同一裁切。可按該頁裁切 → 還原完整圖片 → 套用。這是拍照匯入後自動套用矩形範圍，不是相機快門前即時框線或自動透視校正。
驗證：原有 npm test/語法檢查通過；新增相機/相簿/關閉選項、偵測失敗保留原圖、低對比/觸邊拒絕三個測試通過。真實 Chromium 使用自製文件圖檢查完整相機入口、裁切尺寸、原檔 bytes、手動還原、開關與不明確圖像保留；無 pageerror。未做實際手機相機拍攝驗收。證據 docs/evidence/camera-autocrop-result.json。
