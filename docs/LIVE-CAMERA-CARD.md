# 即時相機與名片欄位修正

## 問題及修正
原「開啟相機」使用 file input capture，網頁只在拍攝完成後收到檔案，不能讀取手機系統相機的即時影像。本輪將主入口改為 getUserMedia 的網頁內相機，保留系統相機備援。

- 約每 220ms 分析一幀；在 video 上顯示白色引導框/黃色候選框/連續三次穩定的綠框。對 letterbox 按 contain 計算座標。
- 使用者按拍攝後，保存完整拍攝 JPEG，經既有裁切/品質/重複檢查流程匯入；自動裁切選項關閉時保留完整圖片。
- 拍攝用途可選文件或名片，名片模式將沿用 OCR 完成後的聯絡欄位擷取。不自動按快門、不新增上傳。
- 關閉、拍攝完成、背景、離頁均停止 tracks；權限失敗或不支援時提供系統相機備援，避免留著鏡頭背景運作。

原 parseCard 取第一行非電話/Email 作姓名，因此品牌/公司也會進入姓名。新 parser 分開公司/品牌、職稱、姓名、電話與 Email：
- 公司關鍵字/明確標籤/大寫品牌候選不當姓名。職稱不當人名。Email 本地部分不拿來猜姓名。
- 明確姓名標籤優先，其次是具有佐證的英文姓名或常見姓氏的中文姓名；多候選或不可靠時留空並提示核對。
- 公司與品牌仍是 OCR 原文字候選，無法從錯誤辨識的 Logo 推測正式公司名稱；需要人工核對。
- 測試以 LITEINI=) 與虛構電話/Email 重現回報：姓名留空，公司候選保留品牌，不含使用者聯絡資料。

## 驗證與界線
npm test（11 檔案）、npm run check、git diff --check 通過；新增五個 parser/框線測試通過。Chromium 154 真實 getUserMedia 搭配合成 Y4M 裝置，連續偵測、綠框、名片模式、拍攝裁切、鏡頭在拍攝/關閉後停止、權限拒絕的 native file chooser 備援、品牌不當姓名與中文公司/人名分離均 PASS，無 pageerror。證據 docs/evidence/live-camera-result.json；可重跑 scripts/live-camera-browser.py（測試埠 4177）。

這不是實體 iPhone 相機驗收，也不是新的 OCR 準確率測試。手機需允許相機權限並以 HTTPS 開啟；深色背景、整張名片完整可見與水平擺放較可靠。邊界不明確仍可拍攝後手動裁切。即時偵測為矩形邊界，非自動四角透視修正。
